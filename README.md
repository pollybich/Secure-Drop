# pollyDrop

Веб-сервис для безопасной временной передачи файлов и текстовых данных.

Отправитель создаёт передачу, задаёт условия доступа и получает ссылку для получателя. Ссылка ограничивается сроком действия, числом получений и, при необходимости, паролем. После наступления условий передачи данные становятся недоступными и удаляются из хранилища.

## Состояние проекта

Проект находится на этапе подготовки к разработке. В репозитории описаны назначение продукта, требования и последовательность работ. Реализация приложения и инструкции запуска появятся по мере разработки.

## Возможности первой версии

- Создание передач без регистрации.
- Передача файлов и текста.
- Уникальные непредсказуемые ссылки.
- Ограничение срока действия и числа получений.
- Одноразовые передачи.
- Дополнительная защита паролем.
- Личный кабинет: список передач, состояния и статистика.
- Ручной отзыв ссылки владельцем.
- Шифрование сохраняемого содержимого.
- Автоматическое удаление недоступных данных.
- Журнал событий без содержимого передач и секретов.
- Развёртывание через Docker.

Предусмотрены публичное использование и внутреннее размещение на инфраструктуре компании. В корпоративном режиме реклама отключается.

## Технологии

- Frontend: React и TypeScript.
- Backend: Java и Spring Boot.
- База данных: PostgreSQL.
- Развёртывание: Docker.
- Содержимое: зашифрованные файлы отдельно от базы метаданных.

## Регистрация и управление

Аккаунт не требуется для создания или получения передачи. Регистрация нужна для личного кабинета и списка собственных передач.

При создании без аккаунта отправитель получает отдельный секретный токен управления для отзыва передачи. Его нужно сохранить и не передавать получателю. Ссылка получения не даёт права управлять передачей. Передачи, созданные после входа в аккаунт, доступны в кабинете владельца.

## Как работает передача

1. Отправитель выбирает файл или вводит текст.
2. Задаёт срок, лимит получений и пароль, если он нужен.
3. Получает ссылку и передаёт её получателю.
4. Получатель открывает страницу, знакомится с условиями и явно запрашивает содержимое.
5. Сервер проверяет условия доступа и разрешает выдачу.
6. После истечения срока, исчерпания лимита или отзыва выдача прекращается, а содержимое удаляется.

Открытие страницы и автоматический предпросмотр ссылки не должны расходовать лимит получения.

### Если скачивание прервалось

На время выдачи сервер атомарно резервирует слот получения. Пока выдача выполняется, тот же слот нельзя использовать параллельно. После успешной отправки всего содержимого сервер фиксирует получение и расходует лимит. При обнаруженном сервером обрыве или ошибке слот освобождается после остановки прежней выдачи, и получатель может попробовать снова.

Повтор разрешён только пока действуют срок, лимит и остальные условия доступа. Открытие страницы и сообщение браузера об успехе сами по себе не подтверждают выдачу. Завершение отправки на сервере не гарантирует сохранение файла получателем; при повторе после обрыва у него уже может быть часть данных.

## Безопасность

- Проверки срока, лимитов, пароля и владения выполняются на сервере.
- Для одноразовой передачи одновременно допускается одна выдача, а лимит расходуется по её успешному завершению на сервере.
- Файлы хранятся отдельно от базы метаданных и в зашифрованном виде.
- Пароли хранятся как стойкие хеши.
- Ключи шифрования и другие секреты не включаются в репозиторий, образы и журналы.
- Рекламным системам не передаются содержимое, пароли и токены ссылок.

Контроль действует в пределах сервиса: получатель может сохранить уже полученную копию. Шифрование хранения на сервере само по себе не означает сквозное шифрование или невозможность доступа оператора сервиса к данным.

## Границы первой версии

Первая версия сосредоточена на временном обмене и управлении доступом. Постоянное облачное хранение, нативные мобильные приложения, корпоративный SSO и индивидуальные интеграции не входят в её содержание. S3-совместимое хранилище рассматривается как дальнейшее развитие.
