Первое обновление pollyDrop: нативная загрузка файлов, устойчивое чтение условий передачи и немедленное удаление доступного содержимого.

### Исправления

- Файлы скачиваются обычным HTTP-ответом `Content-Disposition: attachment` через менеджер загрузок браузера. JavaScript больше не скачивает файл в Blob и не запускает Blob URL после ожидания сети. Короткоживущий одноразовый ticket проверяет пароль, а срок/лимит/отзыв проверяются повторно при реальной выдаче. Подготовка и HEAD не расходуют лимит.
- Временные сетевые сбои при открытии ссылки повторяются автоматически. При окончательном сбое есть кнопка повтора и сообщение на русском вместо `Load failed`. Ошибка фонового обновления больше не скрывает уже полученный текст или результат загрузки.
- Caddy использует HTTP/1.1 и HTTP/2. Убрано объявление HTTP/3 при неопубликованном UDP-порте 443 — это исправление конфигурации, а не подтверждение единственной причины ошибки конкретного iPhone.

### Удаление и интерфейс

- После последнего разрешённого получения либо отзыва содержимое удаляется сразу после фиксации состояния сервером. Для срока ставится таймер, не зависящий от новых запросов пользователей; неудавшиеся удаления повторяются раз в секунду.
- Пример: 10 минут + 3 получения → удаление при истечении 10 минут **или** после третьей полной серверной выдачи, по первому условию.
- Максимум хранения 2 дня. Старые передачи длиннее двух дней сокращаются миграцией до двух дней от создания. Метаданные и резервные копии имеют отдельный жизненный цикл.
- Стрелка над символом `s` в логотипе удалена.

### Обновление сервера

```bash
cd /opt/pollydrop
git pull --ff-only
./deploy/server/update-debian.sh
```

Скрипт проверяет SHA-256 опубликованных сборок, сохраняет ключ и данные, обновляет контейнеры и перечитывает конфигурацию Caddy. Не удаляйте volumes и не генерируйте новый APP_MASTER_KEY. После обновления перезагрузите страницу браузера.

### Границы поведения браузеров

Chrome может спрашивать папку из-за включённого параметра «Спрашивать, куда сохранять каждый файл» в `chrome://settings/downloads`. Сайт не может отключить эту настройку. Встроенный браузер Telegram на iPhone управляется iOS/Telegram; если он ограничивает загрузку, откройте исходную ссылку в Safari кнопкой компаса. WebKit с эмуляцией iPhone проверяет движок, а не физический Telegram.

Серверное завершение отправки не доказывает сохранение на устройстве. Удаление из активного хранилища не означает стирание чужой полученной копии, бэкапа или восстановимых блоков диска. Таймеры требуют работающего backend; после перезапуска просроченные файлы очищаются до готовности API.
