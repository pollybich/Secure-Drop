# Roadmap

План первой версии pollyDrop без календарных дат. Пункты с отметкой выполнены; остальные описывают будущие работы.

## 0. Подготовка проекта

- [x] Описать назначение продукта и границы первой версии.
- [x] Составить первичный реестр требований и критериев приёмки.
- [x] Определить последовательность разработки.
- [x] Выбрать React + TypeScript, Java + Spring Boot, PostgreSQL и Docker.
- [x] Определить создание без регистрации и повтор прерванного скачивания.
- [ ] Зафиксировать архитектурные решения и правила доступа.

## 1. Основа приложения

- [ ] Создать клиентскую и серверную части.
- [ ] Настроить локальное окружение и Docker.
- [ ] Спроектировать базу пользователей, передач и событий.
- [ ] Подготовить миграции и контракт REST API.
- [ ] Настроить конфигурацию через переменные окружения.
- [ ] Реализовать регистрацию, вход, сессии и выход.
- [ ] Разделить гостевые передачи с токеном управления и передачи владельца аккаунта.

**Результат:** приложение запускается локально, база создаётся миграциями, пользователь может войти в систему.

## 2. Основная передача данных

- [ ] Реализовать загрузку файла и ввод текста.
- [ ] Настроить отдельное зашифрованное хранение содержимого.
- [ ] Создавать непредсказуемые ссылки и сохранять параметры передачи.
- [ ] Показывать получателю страницу условий доступа.
- [ ] Выдавать файл или текст только по явному запросу.
- [ ] Обрабатывать ошибки загрузки и получения.

**Результат:** работает полный сценарий создания и получения передачи.

## 3. Ограничения и безопасность

- [ ] Проверять срок действия при каждом запросе выдачи.
- [ ] Реализовать лимит получений и одноразовый режим.
- [ ] Обеспечить атомарность выдачи при конкурирующих запросах.
- [ ] Резервировать слот на время выдачи и расходовать его после успешного завершения на сервере.
- [ ] Освобождать слот после подтверждённого обрыва и остановки прежнего потока, разрешая повтор.
- [ ] Реализовать защиту передачи паролем.
- [ ] Ограничить неуспешные попытки ввода пароля.
- [ ] Проверять владельца при операциях управления.
- [ ] Проверять отдельный токен управления для гостевого отзыва.
- [ ] Исключить содержимое и секреты из журналов.
- [ ] Добавить негативные и конкурентные тесты.

**Результат:** ограничения нельзя обойти параллельными запросами или обращением к API напрямую.

## 4. Управление и удаление

- [ ] Реализовать кабинет со списком, состояниями и статистикой.
- [ ] Добавить ручной отзыв собственной передачи.
- [ ] Удалять истёкшие, отозванные и исчерпавшие лимит данные.
- [ ] Сделать очистку повторяемой и устойчивой к временным ошибкам.
- [ ] Добавить контроль ошибок фоновых задач.

**Результат:** владелец управляет передачами, недоступные данные очищаются автоматически.

## 5. Публичное и внутреннее использование

- [ ] Подготовить публичный режим.
- [ ] Разместить рекламные блоки с учётом приватности.
- [ ] Исключить сторонние рекламные скрипты со страниц создания, получения и кабинета.
- [ ] Подготовить внутреннее размещение на инфраструктуре компании.
- [ ] Отключать рекламу в корпоративном режиме.
- [ ] Описать стандартное обновление и сопровождение установки.

**Результат:** один продукт поддерживает публичную и внутреннюю установку без раскрытия данных рекламным системам.

## 6. Проверка и подготовка выпуска

- [ ] Пройти обязательные сценарии приёмки.
- [ ] Проверить скорость API, конкурентную выдачу и удаление.
- [ ] Проверить обрыв скачивания, повтор, зависшую выдачу и невозможность параллельного использования одного слота.
- [ ] Проверить шифрование, сессии, владение и безопасность журнала.
- [ ] Протестировать чистую установку через Docker.
- [ ] Проверить восстановление метаданных без повторной активации старых передач.
- [ ] Подготовить инструкции пользователя и администратора.
- [ ] Закрыть блокирующие дефекты и выполнить регрессионный прогон.

**Результат:** первая версия воспроизводимо разворачивается и проходит критерии приёмки.

## После первой версии

- [ ] Оценить необходимость S3-совместимого хранилища.
- [ ] Улучшать интерфейс по результатам использования.
- [ ] Расширять возможности внутреннего внедрения по конкретным запросам.

Новые функции добавляются после оценки влияния на безопасность, содержание и нагрузку одного разработчика.
